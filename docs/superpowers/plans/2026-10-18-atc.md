# ATC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build ATC, a board at `atc.plane.home.nakomis.com` that arranges Plane projects and modules into Backlog, Up next and In progress with story points, and make the Plane MCP, BAU and Claude's skills take their priorities from it.

**Architecture:** One FastAPI service (with the built React board as static files) reads Plane's tables and writes only its own `atc` schema in Plane's Postgres on Luke, through a dedicated `atc` role. It runs as a CI-built container on Mace, behind Leia's mTLS vhost. The Plane MCP and BAU are HTTP clients of its API; neither touches Postgres.

**Tech Stack:** Python 3.12, FastAPI, psycopg 3 (+ psycopg_pool), uv, ruff, pytest, testcontainers (Postgres 15.19); React 19, Vite, Tailwind 4, Biome, Vitest, pnpm, @dnd-kit; Docker; Ansible (home-infra); GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-18-atc-design.md` (approved 18 Oct 2026). Read it with this plan; where they differ, the spec wins unless this plan records a correction (see "Corrections to the spec").

## Global Constraints

- Columns are data-driven; the initial set is keys `backlog`, `next`, `in_progress`, labels "Backlog", "Up next", "In progress".
- `max_points` = 100, configurable (`ATC_MAX_POINTS`). Points are any integer 1..`max_points`; no Fibonacci, no 8 cap. 1 point ≈ 1 day of Martin's own work.
- `points_source` ∈ `claude-estimate | martin | mcp`.
- **Open** = Plane state group not `completed` or `cancelled` (triage, backlog, unstarted, started all count), and the item is not soft-deleted (`deleted_at`), not archived (`archived_at`), not a draft (`is_draft`), in a project that is neither deleted nor archived.
- ATC never writes Plane's tables and never runs Plane migrations. It writes only schema `atc`, as role `atc`. Password: SSM `/atc/postgres/password` (eu-west-2, profile `nakom.is-admin`), 64 lowercase hex characters.
- The API uses Plane UUIDs internally and returns project identifiers alongside them.
- ATC adds no auth of its own; Leia's mTLS is the gate. The MCP and BAU use the client certificates they already use for Plane.
- Ticket order within a module is Plane's `issues.sort_order`; ATC stores no ticket order.
- Rows are created lazily; a Plane project/module with no ATC row is Backlog, bottom.
- Python 3.12, `uv`, ruff (line length 110, rules E F I B UP), coverage floor 70% in every Python and web package touched. pnpm pinned via `packageManager`; never npm lockfiles.
- British English in code comments, UI copy and docs.

## Corrections to the spec (found while grounding this plan)

1. **Registry.** `docker.home.nakomis.com` is Nexus's pull-only Docker Hub proxy; a push there 404s. Estate images go to the hosted repository **`registry.home.nakomis.com`** (`ALLOW_ONCE`, tags never move; home-infra `docs/runbooks/nexus.md`). ATC's image is `registry.home.nakomis.com/nakomis/atc:<version>-<sha7>`. No box pulls from it yet, so Mace needs `/etc/docker/certs.d/registry.home.nakomis.com/` (Task 11).
2. **TLS certificate.** Leia's front certificate covers `*.home.nakomis.com` and `*.<box>.home.nakomis.com` only (checked live 18 Oct 2026). A wildcard does not match two labels, so `atc.plane.home.nakomis.com` needs `*.plane.home.nakomis.com` added to Leia's `certbot_domains` (Task 11). DNS is already fine: the Route 53 wildcard resolves `atc.plane.home.nakomis.com` (checked with `dig`).
3. **Versioning.** The house deployment tracker (`nakomis-infra` `compute-version` / `record-deployment`) needs a per-project AWS CI role (`GithubCiStack`, both accounts) on the tracker's allow-list. ATC has no AWS infrastructure, so CI tags images `<api/pyproject.toml version>-<sha7>` and bumps the patch while a tag exists. Adopting the tracker later means adding a `GithubCiStack`; out of scope here.
4. **Restore ordering.** `pg_dump` of `plane` will contain `ALTER SCHEMA atc OWNER TO atc` and grants to `atc`; Luke's restore runs `psql -v ON_ERROR_STOP=1`, so a restore onto a fresh cluster fails unless role `atc` exists first. Task 1 creates the role before the restore tasks and the schema/grants after them.

## API contract (fixed by Tasks 4–8; consumed by Tasks 9, 12–15)

All JSON. UUIDs as strings. `ItemView`, `ModuleView` and `Card` are the board's building blocks.

```text
ItemView   = {id, ref, name, state, state_group, priority, points: int|null, points_source: str|null, url}
ModuleView = {id, name, unsorted: bool, status: str|null, points: int, unestimated: int, items: [ItemView]}
Card       = {kind: "project"|"module", id, project_id, identifier, label, points, unestimated, modules: [ModuleView]}
             project card: id == project_id, label == project name, modules = that project's modules in this column, in card order
             module card:  id == module id,  label == "IDENT · Module name", modules = [that one module]
Column     = {key, label, points, unestimated, cards: [Card]}
ProjectMeta= {id, identifier, name, column, repo: str|null, deploys, deploy_action, bau_enabled}
NextItem   = {id, ref, name, points: int|null, url, module: {id, name, unsorted}, project: {id, identifier, name}}

GET  /api/board[?all=true]          -> {columns: [Column] (display order), max_points, generated_at}
POST /api/move     {kind, id, to_column, before_id?: uuid|null}       -> board   (404 unknown id; 422 bad column/before_id)
POST /api/reorder  {project_id, module_id, before_id?: uuid|null}     -> board   (422 if module not in that project card)
GET  /api/next                      -> {column: "in_progress"|"next"|null, next: NextItem|null, runners_up: [NextItem] (≤2)}
GET  /api/priority                  -> {refs: [str]}   every open item, priority order
GET  /api/projects[?bau_enabled=true] -> [ProjectMeta] in board priority order
GET  /api/projects/{uuid|IDENT}     -> ProjectMeta     (identifier match is case-insensitive)
PUT  /api/projects/{uuid|IDENT}     {repo?, deploys?, deploy_action?, bau_enabled?} -> ProjectMeta
GET  /api/work-items/{uuid}/points  -> {id, points: int|null, points_source: str|null, updated_at: str|null}
PUT  /api/work-items/{uuid}/points  {points, source, if_unestimated?: bool=false} -> same shape
                                    (404 unknown/deleted Plane item; 409 if_unestimated and already set; 422 range/source)
GET  /api/work-items?project=IDENT&unestimated=true -> [{id, ref, name, description, module, state_group}]
GET  /api/health                    -> {ok, missing: [str], last_reconcile: str|null, hidden: {projects, modules}}  (503 when not ok)
```

**Priority order** (used by `/api/next`, `/api/priority`, `/api/projects` and item-to-module assignment): columns by `priority` (In progress, Up next, Backlog), then card order within the column, then module order within a project card, then items by `(sort_order, priority rank urgent→none, created_at, sequence_id)`. "First of its modules in board order" (spec §11) means first in this priority order.

## Review Focus

1. **An item in several open modules** (76 live today): it must appear and count once, under the first of its modules in priority order; column totals must equal the sum over unique open items. Test: Task 4 `test_item_in_two_modules_counts_once`.
2. **Duplicate `sort_order`** (465 groups live): order within a module must be deterministic, falling back to priority rank, then `created_at`, then `sequence_id`. Test: Task 6 `test_sort_order_ties_break_by_priority_then_created`.
3. **Rank collation**: ranks are compared by Postgres, whose default collation is not byte order; `'B' < 'a'` must hold or drags land in the wrong place. Rank columns are `COLLATE "C"`. Test: Task 5 `test_db_orders_ranks_bytewise`.
4. **Plane rows vanishing mid-life** (project archived, module deleted, item removed from a module, which soft-deletes `module_issues`): the item must fall back to Unsorted or disappear, never be counted from a dead row. Tests: Task 4 `test_soft_deleted_membership_is_ignored`, Task 8 `test_reconcile_hides_archived_project_and_unhides_on_return`.
5. **Re-running the points pass after Martin has corrected points**: it must never overwrite a number that is already set. Tests: Task 7 `test_if_unestimated_refuses_to_overwrite`, Task 13 `test_pass_skips_items_estimated_meanwhile`.

Layout rules (spec §5, §11), all in `build_board`:
- A project or module with no ATC row (or a `hidden_at` row) is treated as Backlog; rowless ones sort after ranked cards, by Plane `created_at`. Unsorted with no row takes its project's column.
- Column `C` contains a **project card** for each project whose column is `C` (always, even when empty), and a **module card** for each module (incl. Unsorted) whose column is `C` while its project's column is not. Project ranks and module `column_rank`s share one rank space per column; cards sort by it.
- A project card lists its modules whose column is `C`, by `card_rank`.
- Item assignment: compute the layout first; walk `priority_modules`; each open item goes to the first **open** module (status not `completed`/`cancelled`) it belongs to; items with none go to their project's Unsorted.
- Collapsing unless `include_all`: modules with status `completed`/`cancelled`; Unsorted with no items; projects with no open items anywhere (with all their cards).
- Points: a module's `points` = sum over its items' points; `unestimated` = count of items without points; cards and columns sum their modules.

Rules (spec §5):
- **Module to column B:** if its project's column is B, it joins the project card at the bottom (`card_rank = after(last in card)`); otherwise it becomes a module card at `before_id` (rank between the neighbouring cards in B) or the bottom.
- **Project A → B:** project's column = B, rank from `before_id` or bottom. Every module of the project currently in A or B ends up in B, inside the card, ordered: modules already in B first (in their current card order in B), then those from A (in their card order in A); `card_rank`s are reassigned in that order. Modules in the third column are untouched. Moving within the same column is a reorder of the card.
- **`before_id`** must be a card currently in `to_column` (a project id for project cards, a module id for module cards) and not the moved item itself; otherwise `Invalid`.
- **Reorder:** the module must belong to `project_id` and share its column; `before_id` (if given) must be a module in the same card. Writes one row.
